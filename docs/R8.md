# Release builds with R8

R8 runs in the **integrating Android application**. Gradle automatically imports the consumer rules packaged in the AAR. Do not add a blanket keep rule for the SDK.

## App configuration

```groovy
android {
    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'),
                'proguard-rules.pro'
        }
    }
}
```

With AGP 9.0.1, remove `android.nonFinalResIds=false`, `android.r8.strictFullModeForKeepRules=false` and `android.r8.optimizedResourceShrinking=false` from `gradle.properties` if present. Use the R8 defaults and retain the other integration settings in the README.

Keep only application-specific reflection rules in `app/proguard-rules.pro`. Do not add `-keep class com.becomedigital.** { *; }`, `-keep class aws.smithy.kotlin.runtime.** { *; }`, `-dontobfuscate` or `-ignorewarnings` as general workarounds: these restrict optimization or hide actual integration errors.

## Packaged protections

- Reflectively read JSON models, typed response fields and public status wire names.
- Dynamically resolved host text overrides with the `intro_*` and `atdp_*` prefixes.
- The Capture 1.2.0 native callbacks and native method names. This supplements the empty consumer rules in the supplied legacy Capture AARs.

Provider rules still apply from their dependencies. Keep the dependencies and versions specified in the README. The distributed AAR retains its public API; R8 optimizes the final application rather than publishing a pre-obfuscated AAR. Savings depend on actual usage. R8 does not shrink native libraries or guarantee a particular APK size reduction.

## Validation and diagnostics

Build `./gradlew :app:assembleRelease` or `./gradlew :app:bundleRelease`. Retain each release's `app/build/outputs/mapping/release/mapping.txt` for retracing obfuscated crashes; do not publish credentials or personal data.

Before shipping, test the **optimized release** on a physical device: permissions, automatic and manual capture, document sides, retry, facial validation, cancellation, custom text, and typed results and errors. A successful build does not replace these tests.

Reference: [Android library optimization](https://developer.android.com/topic/performance/app-optimization/library-optimization).
