# Become Android SDK — Capture legacy

This guide matches the `becomedigitalsdk.aar` distributed on `feature/mobile-contract-parity`. It provides Compose verification screens with onboarding and authentication, typed results, contract-controlled appearance, and Microblink Capture legacy document capture.

## Validated integration versions

| Component | Version or value |
| --- | --- |
| Minimum Android API | 24 |
| `compileSdk` / validated `targetSdk` | 36 / 36 |
| Build JDK used for validation | 21 |
| Java and Kotlin bytecode target | 11 |
| Gradle wrapper | 9.2.1 |
| Android Gradle Plugin | 9.0.1 |
| Kotlin and Compose compiler plugin | 2.2.10 |
| Capture Core / Capture UX, supplied local AARs | 1.2.0 / 1.2.0 |
| Compose BOM | 2026.06.00 |
| Activity KTX / Activity Compose | 1.12.4 / 1.12.4 |
| Amplify UI Face Liveness / AWS Cognito | 1.10.0 / 2.33.0 |
| CameraX | 1.5.3 |

JDK 21 runs the build; the Java 11 setting below is the generated bytecode target. These are different settings. Keep the Compose compiler plugin aligned with Kotlin and Compose libraries aligned through the BOM.

The supplied AAR is the production build. The host's Debug/Release variant does not change the SDK environment, and `BDIVConfig` has no environment selector. A separate development build and a valid license for its application ID are required when testing another environment.

## Installation and dependencies

Copy these three files into the host application's `app/libs` directory:

- `becomedigitalsdk.aar` from this repository's root.
- `capture-core-1.2.0.aar` from `libs`.
- `capture-ux-1.2.0.aar` from `libs`.

A local AAR has no transitive dependency metadata. Declare the host dependencies explicitly, including those used by optional facial steps. Remove other Capture versions and BlinkID Core/UX migration dependencies when integrating this build.

## License and permissions

Add the Capture license issued for the app's `applicationId` as **`app/src/main/assets/com.become.mb.key`**. Keep its contents out of source control.

The AAR declares Internet, camera, and optional coarse-location permissions. Obtain the camera runtime permission before starting a flow that requires it. Optional location denial does not block verification. Retain the SDK's merged activity and FileProvider declarations; no custom storage path is required for document capture.

## Initialization

Register the callback before starting the SDK and retain the callback manager while the flow is active. The public spellings `clienId`, `DocumetType`, and `BecomeInterfaseCallback` are retained for compatibility.

```kotlin
import androidx.appcompat.app.AppCompatActivity
import com.becomedigital.sdk.identity.becomedigitalsdk.core.callback.BecomeCallBackManager
import com.becomedigital.sdk.identity.becomedigitalsdk.core.callback.BecomeInterfaseCallback
import com.becomedigital.sdk.identity.becomedigitalsdk.core.callback.BecomeResponseManager
import com.becomedigital.sdk.identity.becomedigitalsdk.models.BDIVConfig
import com.becomedigital.sdk.identity.becomedigitalsdk.models.BDIdentityVerificationResponse
import com.becomedigital.sdk.identity.becomedigitalsdk.models.DocumetType

class DemoActivity : AppCompatActivity() {
    private val callbackManager = BecomeCallBackManager.createNew()

    fun startOnboarding() {
        BecomeResponseManager.getInstance().registerCallback(
            callbackManager,
            object : BecomeInterfaseCallback {
                override fun onFinish(response: BDIdentityVerificationResponse) {
                    when (response.responseStatus) {
                        BDIdentityVerificationResponse.StatusType.SUCCES -> {
                            response.onboarding?.let { _ -> /* Creation result. */ }
                            response.verification?.let { _ -> /* Final confirmation. */ }
                            response.authentication?.let { authentication ->
                                // Evaluate authentication.result separately.
                                val accepted = authentication.result
                            }
                        }
                        BDIdentityVerificationResponse.StatusType.ERROR -> {
                            // Restore the host UI and offer a new attempt.
                        }
                        else -> Unit
                    }
                }
                override fun onCancel() {
                    // Restore the host UI without marking verification approved.
                }
            }
        )
        val config = BDIVConfig(
            "YOUR_CLIENT_ID", "YOUR_CLIENT_SECRET", "YOUR_CONTRACT_ID",
            arrayOf(DocumetType.DNI, DocumetType.PASSPORT, DocumetType.LICENSE),
            true, "YOUR_USER_ID"
        )
        config.flow = BDIVConfig.Flow.Onboarding
        config.themeMode = BDIVConfig.ThemeMode.system
        BecomeResponseManager.getInstance().startAuthentication(this, config)
    }
}
```

### Public configuration

| Parameter | Default | Meaning |
| --- | --- | --- |
| `clienId`, `clientSecret`, `contractId` | Required constructor arguments | Nonempty client credentials and contract identifier. |
| `userId` | Required constructor argument | Nonempty for `Authentication`; onboarding also accepts an empty string. |
| `documentTypes` | Required constructor argument | `DNI`, `PASSPORT`, `LICENSE`. The contract filters this list. An empty array uses the contract's available types. |
| `allowLibraryLoading` | Required constructor argument | Retained for constructor compatibility. It does not select or override the current contract's document capture mode. |
| `flow` | `Flow.Onboarding` | `Onboarding` or `Authentication`. |
| `performVerificationCheck` | `true` | Wait for final onboarding confirmation. Set `false` to return the creation result directly. |
| `pollingMaxAttempts` | `0` | Maximum result checks; `0` means no attempt limit. |
| `pollingTimeoutSeconds` | `2` | Timeout in seconds for each result check. Use a larger value for slow connections. |
| `debugLogsEnabled` | `false` | Enable optional client diagnostics. |
| `preventScreenCapture` | `false` | Enable the SDK's screen-capture protection when `true`. |
| `country`, `state` | `null` | Optional two-letter country code or comma-separated country list; optional US postal state code. |
| `nationalIdType`, `documentNumber` | `null` | Optional prefilled document details. |
| `nationalIdTypeChoices` | Empty array | Optional document subtype choices. |
| `themeMode` | `ThemeMode.system` | `light`, `dark`, or the device's preferred appearance. |

Set optional fields through `BDIVConfig` setters before starting the SDK. For authentication, use `Flow.Authentication`, an existing nonempty `userId`, and `emptyArray()` when documents are not required.

### Documents and presentation

The SDK displays the steps and document types available for the contract. A supplied document list restricts the request to supported types; when there is no overlap, the SDK uses the contract list. A single document type is still displayed for confirmation. Passport capture uses the front; other required sides follow the contract.

Complete frames are used for document uploads. Cropped, perspective-corrected images are used for preview; if no crop is available, the preview can show the complete frame. Full-frame uploads preserve the image bounds while applying JPEG encoding and size limits.

The SDK applies the flow, appearance and text assigned to the contract. `BDIVConfig` does not configure flow copy or design. Local resources are optional for native component instructions and technical loading/network labels; see the [native text guide](docs/PERSONALIZACION_TEXTOS.md).

An animated loader remains visible until the first configured screen is ready. Its initial color uses the host's primary theme color, then its accent color. Document-only contracts do not require a facial result to complete.

## Typed results and errors

`onFinish` receives `BDIdentityVerificationResponse`, containing `responseStatus`, `message`, and optional flow-specific objects:

| Object | Public fields | When to inspect it |
| --- | --- | --- |
| `onboarding` | `code`, `message`, `urlResource`, `userId` | Direct creation result when `performVerificationCheck` is `false`. Creation is not final approval. |
| `verification` | `urlGetData` | Confirmed onboarding result when waiting for completion. |
| `authentication` | `company`, `confidence`, `executionId`, `liveness`, `result`, `userId` | Authentication result; evaluate the Boolean `result` separately. |

The response object provides `toJson()`. Do not expect a response dictionary. `SUCCES` retains its historical spelling; other declared statuses are `ERROR`, `PENDING`, `NOFOUND`, and `CANCEL`. User cancellation normally arrives through `onCancel()`. Message text is not a stable error code. See [error handling](docs/ERRORES.md).
